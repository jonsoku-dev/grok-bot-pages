세레스가 Claude Code 세션 10병렬을 git worktree로 나누다 포트 충돌·브랜치 혼선·Docker 디스크·서브에이전트 본저장소 쓰기 등 5벽을 밟았다. .git 공유 슬롯 레지스트리로 포트에 slot×100을 더하고, compose -p/container_name 고정 제거, disposable worktree는 .claude/worktrees/에 둔다. Docker 풀스택은 메모리상 2–3본이 상한이었다.

  • 왜 중요한가: 세션 수보다 Docker/포트 공유층이 병렬 상한. 공유 .git 레지스트리와 고정 container_name 제거.
  • 추천: 읽기 — Claude Code 10병렬을 worktree로 나누다 포트·브랜치·Docker 디스크·서브에이전트 본저장소 쓰기를 밟음. harness 운영에 맞음. 슬롯×100 포트와 compose -p가 Isolations의 실제 한계. 풀스택은 메모리상 2–3본. 10세션 재현 EXPERIMENT 아님.
  • 주의할 점:
    • Docker Desktop ~4GiB에서 스택당 ~1.6GiB. 환경마다 상한이 다름.
    • resolve_slot이 부모에서 fail하지 않으면 포트가 조용히 겹침.
    • 서브에이전트가 본저장소에 쓰는 실패는 worktree만으로 안 막힘.
  • 다음 단계: 포트 슬롯·compose -p·서브에이전트 cwd 세 줄만 현재 병렬 세션과 대조. 10 worktree 기동·외부 게시 없음.

LY Corporation Agent i / Agent Builder + Agent Runtime — lycorp-agent-i-platform​

LINE 야후(LY Corp)가 Agent i용으로 Agent Builder(노코드 워크플로)와 Agent Runtime을 내제화했다. Builder는 React Flow·IR 검증 후 공개하고, Runtime은 IR을 LangGraph로 컴파일한다. K8s Namespace 샌드박스·ACL·MCP/내부 API 접근 검증으로 만들기와 안전 실행을 같이 잡는다.

  • 왜 중요한가: 만들기(Builder IR)와 안전 실행(Namespace+ACL)을 한 쌍으로 두는 체크리스트. 자격증명은 워크플로에 박지 않고 필요할 때 가져옴.
  • 추천: 읽기 — Agent Builder가 IR 검증 후 공개하고 Runtime이 LangGraph로 컴파일하며 K8s Namespace·ACL로 MCP/내부 API를 런타임 검문. harness·MCP·sandboxing에 맞음. 내부 Agent i 플랫폼이라 설치 EXPERIMENT/ADOPT 아님. A2A는 미래, 지금은 독자 프로토콜. 브랜드 비가중. relatedCategories는 [] 유지.
  • 주의할 점:
    • 내부 플랫폼. 이 글만으로 재현 설치 불가.
    • LangGraph는 IR 컴파일 타깃이지 기본 스택 교체 근거가 아님.
    • Gateway가 독자 프로토콜. 향후 A2A/MCP 클라이언트와 어긋날 수 있음.
  • 다음 단계: IR 검증 vs Namespace+ACL vs 자격 비임베드 세 줄만 현재 에이전트 런타임과 대조. 플랫폼 구축·외부 게시 없음.
